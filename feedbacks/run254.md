2026-10-29, release 0.25.4. New compiler/src/cli/run.vl (597 lines);
main.vl's build moved into `pub fn build`; small changes to base/term.vl,
base/diag.vl, tools/proc.vl, tools/query/cache.vl, tools/testrun (two shared

transcript (tests/refactor/run254.t, 30 commands) and docs. 39 files,

## Verdict

The compiler's own tools carried a cross-cutting change through seven
modules with few wasted turns: `query context` found the cache mechanism of
`volec test` in two calls, and checked edits caught every mistake at once.
Time went to the hooks refusing reads of a file I had just written, to
edits refused one at a time when two items depend on each other, and to a
slow shared machine (an affected run of 588 cases took about 9 minutes).

## What worked

- `volec query context newer_tach` and `query context cache_dir`: source,
  calls and callers in one answer; that is how I found `volec test`'s
  key file plus `find -newer` check and its in-place install, and reused
  them (`testrun::program::up_to_date`, `install`) instead of writing a
  third mechanism.
- `volec query items std::fs` / `std::process` / `std::env`: signatures and
  lines; showed at once that `std::process::Command` holds at most 32
  arguments (`args: [[u8]; 32]`), so `volec run` needed its own fork/exec.
- `refactor signature crate::cli::run::is_out_word --add 'dir_at: i64 = -1'`
  ("added parameter ..., 3 calls"), then `edit patch` to drop the default,
  then `refactor rename ... left_out`: three checked calls for a signature
  change across a file.
- `edit patch NAME --old A --new B ... --in OTHER --old C --new D`: one
  checked edit over five items of run.vl (struct, two functions, callers).
- `edit patch NAME --pairs FILE` with `<<<<<<< OLD` blocks for the long help
  and explain strings (backslash continuations, quotes) that are painful as
  shell arguments.
- The check hook's diffs ("1 error (1 new)", "0 errors (1 fixed)") after
  each Edit-tool change; the error texts were exact: `no method 'ends_with'
  on type '[u8]' | help: ... text is str`, `distinct.mix: 'name' is '[u8]'
  where 'str' goes`.
- $VOLE_CACHE_TRACE (a file the tools' cache writes `hit`/`miss` into)
  was already the house's way to test a cache; `run fresh` / `run build`
  lines went into it, so the transcript checks the cache hit without timing.
- `bootstrap/bootstrap.sh --dev --no-suite`: always `fixpoint ok`, about a
  minute here under load 22-26.

## What cost time, ranked

### 1. Reading my own new file was blocked
`grep -n 'ends_with\|c_of(name)' compiler/src/cli/run.vl` and `perl -0pi
-e ...` on it: `blocked hook.query-first ... compiler/src/cli/run.vl is 531
lines` and `blocked hook.edit-tool ... (perl -pi) rewrites the compiler's
source`. The file was minutes old and written by me with the Write tool.
Earlier, `cat compiler/src/main.vl` (430 lines) was blocked and `volec
query show compiler/src/main.vl` refused it: `error query.too-long: ...
has 430 lines (show prints a file of at most 200)`. The Read tool read
both. 3 turns. What would have saved them: the hook letting a file the
session created itself be grepped, or `query show FILE --all`.

### 2. Two dependent edits refused one by one
`edit patch crate::tools::help::HELP` (a 41st entry) and the array length
`HELP_COUNT` / `[Help; 40]`: each alone gave `error edit.breaks: 1 new
error; nothing written`. The note (`note edit.together: several steps are
one call`) said what to do, but a static and a const are two items, and
`--old/--new` with long backslash-continued strings in the shell failed
on quoting; I wrote a `--pairs` file. Same for `edit insert` of a function
calling a not-yet-declared extern (`undefined variable 'signal'`): insert
the extern first, then the function. 3 turns.

### 3. A new diagnostic prefix needs a test runner edit nobody mentions
After adding `run.no-main` and friends with explain entries,
`tests/refactor/run.sh` said `FAIL self_explain: ... not a code:run.args
run.file run.no-main run.option`: the runner greps `c"(query|edit|...|unsafe)\.`
for codes, a hard-coded prefix list. `guide how#add-diagnostic` did not
say so (I added a sentence). 1 turn plus a 9-minute affected run.

### 4. Guide and help limits found only by the suite
`FAIL guide-embedded: compiler/src/guide/text is stale: run
compiler/guide/embed.sh` and `FAIL help-: ...` (`volec --help` must stay
within 15 lines; one new row made 16). Both known rules, neither said by
the hooks when I edited compiler/guide/*.md or help.vl; each cost an
affected run (531 s at -O0). A check-after-edit note for guide .md
("run embed.sh") and a line count in help.vl's header would have saved it.

### 5. main's argument loop and help scan ignored `--`
Found while designing: `volec run -- --json` would have lost `--json`
(stripped for DIAG_JSON anywhere), and `-- --help` printed volec's help.
Fixed in main.vl (words after `--` pass as they are). Not a tool problem,
but the same bug was latent for `probe -- ARGS`.

### 6. Language: bytes vs text
`[u8]` has no `ends_with` (str does); I wrote a local `ends()` as hint.vl
already had. `c_of` takes `str`, so a `[u8]` name needed a copy through a
buffer (`distinct.mix` error). Clear errors; small cost.

### 7. My own mistakes, for the record
A zsh `for a in "run x y"` loop passed one word (`cannot read run
examples/...`); a test program reading stdin blocked a `--color=always`
run until the 120 s timeout.

## Never used

`probe`, `reduce`, `rewrite`, `query impact`, `batch` (except to see that
`batch` refuses `run`: `error batch.usage: 'run' is not a command batch
runs`), `fix --suggested` (no error needed it). Not needed for this task.

## Fix list, in order

1. [hook] Let reads (grep, sed -n) and rewrites of a .vl file the session
   itself created pass the query-first hook, or say "use the Read tool"
   in the block's first try: line for a whole file over 200 lines.
2. [test] tests/refactor/run.sh's self_explain: find codes by `diag(c"...",
   c"CODE")` and explain's table instead of a hard-coded prefix list.
3. [hook] check-after-edit: after an edit of compiler/guide/*.md, say
   `compiler/guide/embed.sh` is needed (the suite's guide-embedded fails
   otherwise).
4. [tool:edit] `edit patch` over a static array and its count const in one
   call without `--pairs` (e.g. `--in` taking a const), or a `refactor`
   that grows an array literal and its length together.
5. [std] std::process::Command: no 32-argument limit, an `env_remove`, and
   a way to leave SIGINT to the child; then `volec run` needs no unsafe.
6. [std] `ends_with` / `starts_with` on `[u8]`.
7. [lang] A `\` line continuation in a string drops the next line's
   leading spaces, so help texts lose their indentation (`volec lsp
   --help` shows it too); a way to keep them, or a text block in help.vl.
8. [docs] guide how#add-diagnostic: the code-prefix list (done here), and
   the 15-line limit of `volec --help` (tests/guide/run.sh).
