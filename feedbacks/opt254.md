# Feedback: opt254, the optimizer's Vec facts (modernization step 2)

2026-10-29, release 0.25.4. Two alias facts for std's Vec in a new
middle/vecfacts.vl (about 330 lines), their use in gvn.vl's `may_alias`,
LICM (licm.vl: a Vec header's loads from a reference parameter, a load at
a static's address made in the loop, `hoist_invariant_loads` for the
vectorizer) and vectorize/mod.vl; six tests/run cases, the bench pair
bench/vecloop/ with its runner, the guide's unsafe rules, docs.

## Verdict

The optimizer was easy to change and hard to measure: `query context`
and the check hook made the code change itself a few hours' work, and
the fixpoint plus the IR CHECKs caught nothing wrong. What cost the most
was proving the change is worth its compile time (no per-pass
instruction counts without building a special compiler, no reason from
`--vec-stats`) and proving the tests can fail (the first adversarial
tests passed against a deliberately broken compiler; I had to make
mutants by hand to find cases that tell).

## What worked

- `volec query context NAME` (fn_param, param_mode, lower_addr,
  inherit_into): source, callees and callers in one call; it found 0.17's
  `param_frozen`/`params_disjoint` machinery, which the new facts build on.
- The check hook after every Edit: `undefined variable 'vec_apart' |
  help: add use crate::middle::vecfacts::vec_apart;`, and `volec fix
  --suggested compiler/src/main.vl` made four private items `pub` in one
  checked edit (`fixed 4 pubs`).
- `bootstrap/bootstrap.sh --dev --no-suite`: about 20 s, the fixpoint
  checked each time; the new optimizer compiled the compiler and itself
  identically from the first build.
- `--emit-ir` and `--emit-asm` with `#[inline(never)]`: the before/after
  evidence for every kernel, and the CHECK / CHECK-NOT directives turned
  it into a test that fails on the old compiler (`tests/run.sh -c OLD`).
- `--check-alloc` in the adversarial cases: a stale `ptr` after a growth
  would fault instead of reading freed memory quietly.
- `volec query unsafe FILE` listing my new sites as `missing both`, and
  `tests/unsafe_audit.sh -u` lowering the baseline (4374 to 4373) once
  they were justified.
- `--time-passes` with C's `clock` replaced by an instruction count
  (docs/optimizer.md's 0.17 method, `volec main.vl iclock.c -o icount`):
  per-phase instructions, stable to 0.3% at a load of 40.

## What cost time, ranked

### 1. Compile cost: finding which part of the change cost what
The -O2 self-compile rose 8% in instructions after the first version
(51.2G to 55.1G, `/usr/bin/time -l volec --no-cache -j1
compiler/src/main.vl -c`). Finding the cause took about 10 builds of
variants by hand (one piece switched off with `if false &&`, built by
the old compiler, measured twice): LICM hoisting every static's and
slot's address out of every loop was 4.7 points of it, the facts' own
analysis 0.4, their downstream effects 1.2. About 25 turns. What would
have saved them: `--time-passes=instructions` built in (the `clock`
trick needs a special build), and a per-pass instruction count in
`--stats`. The first cache-on measurement misled me too (57G against
61G, the code cache warm for one compiler only): `--no-cache` should be
in the docs' measuring recipe.

### 2. Adversarial tests that cannot fail
My first five adversarial cases passed against a compiler whose fact 1
claimed every parameter frozen, and against one whose fact 2 dropped the
same-header test: a push writes the header through the same base
(caught before the facts), and a growth calls `reserve_more` (calls are
handled apart). Only a call-free header write through a different
pointer tells (`truncate` through a pointer kept in a static or in
another Vec's buffer). Building the mutants: 4 turns. What would have
saved them: a mutation mode (`volec test --mutate PASS` flipping one
fact) or, cheaper, a line in `guide how#a-pass` saying that an alias
fact's test needs a write through another base with no call.

### 3. Why the let-parameter loop was not vectorized
`--vec-stats` printed `vector loops 0, overlap tests 0` and no reason.
The reason (vectorize/legality.vl `analyze`: an access address that
depends on a load in the loop, `loads_in`) took reading 300 lines of
legality.vl and mod.vl; then the fact that LICM runs after the loop
passes (opt.vl `loop_pipeline`). About 5 turns. A `--vec-stats=FN`
printing each loop's rejection would have said it at once.

### 4. `edit patch` hid the error of a refused edit
`volec edit patch compiler/src/middle/licm.vl --old A --new B --old C
--new D` printed only `note edit.together: several steps are one
call...` and a `try:` adding `--no-check`; the error (`undefined
variable 'size'`, the name declared below the new use) appeared only
after `--no-check` and the hook's check. 2 turns. The refusal should
print the error it refused for. (tools/agent-feedback)

### 5. The hook and my own new file
`query-first.py` blocked a Python rewrite of compiler/src/middle/
vecfacts.vl, a file I had created an hour before, and also a Python
script that only read it and wrote to the scratchpad (the path in the
script was enough). `edit replace NAME < file` did the job. 2 turns. A
new untracked file could be exempt, or the block could say that `edit
replace` takes several items' text.

### 6. `tests/run.sh =NAME` under zsh
`tests/run.sh =opt_vecfacts_header` printed `(eval):1:
opt_vecfacts_header not found` (zsh's equals expansion); quoting it
works. 1 turn; recorded twice already by others today.

### 7. Editing files while the suite ran
I edited two of my test cases while `tests/run.sh -O 2` ran; the fmt
suite's `compiles` check (the tree against a copy taken at the start)
then failed with `differ: tests/run/opt_vecfacts_let_raw.vl`. A rerun
was needed. The failure could say the file changed during the run
(mtime after the copy).

### 8. A compiler linked by `volec -o` ran 7x slower
`volec compiler/src/main.vl -o volec.B` gave a compiler whose -O2
self-compile took 36 s user and 357G instructions; the same source built
with `-c` and linked by `cc` took 5.3 s and 54G. A small program
compiled the same with both. I did not find why (recorded with
tools/agent-feedback); it cost 3 turns of confusion while measuring.

### 9. A fact resting on an attribute that another branch widened
Fact 1 first followed any `#[sealed]` std struct. The merge of
release-0.25.4 sealed Mutex, MutexGuard, Sender and others; a Mutex's
let method writes the value inside through a raw pointer, so the fact
would have become unsound with no conflict and no failing test. I found
it reading the merge's diff, and narrowed the path to an explicit list
of std's Vec wrappers (String, Buf, PathBuf, BinaryHeap, MinHeap) with a
Mutex case added to opt_vecfacts_let_raw. 3 turns. What would have
caught it: an attribute meaning "only inout methods change its fields"
that the checker verifies, instead of reusing `#[sealed]` (which means
"fields private to std").

## Never used

- `refactor`, `rewrite`: no source idiom changed.
- `probe`, `reduce`: no miscompile to chase; the fuzzers and the cases
  found none.
- `tests/affected.sh --list` until the end: middle/ maps to @codegen
  (every -O1/-O2 program), so it is the whole suite twice anyway.

## Fix list, in order

1. [tool:time-passes] `--time-passes=instructions` (or `--stats`) counting
   instructions retired per phase without a special build; and
   docs/optimizer.md's measuring recipe with `--no-cache -j1`.
2. [tool:vec-stats] `--vec-stats=FN`: each loop considered, vectorized or
   the first reason it was not (`loads_in` on an access address, a call,
   not counted, cost).
3. [tool:edit] `edit patch` and `edit replace` print the error they
   refused for, not only `note edit.together`.
4. [docs] `guide how#a-pass`: an alias fact's adversarial test needs a
   write through another base with no call in between (a push is
   caught by the same-base rule, a growth by the call rule), and a
   mutant to show the test can fail.
5. [hook] query-first.py: let Python and sed write files the branch
   added (untracked or new in the branch), and do not block a script
   that only reads compiler source.
6. [test] tests/fmt/run.sh's `compiles`: name a file changed during the
   run as such instead of `differ`.
7. [docs] AGENTS.md: write `tests/run.sh '=NAME'` quoted (zsh).
8. [build] find why the compiler linked by `volec -o` runs its
   self-compile 7x slower than the same object linked by `cc`.
9. [lang] an attribute (or a checked property) for "no let method writes
   a field, through a raw pointer either", which the optimizer's facts
   could rest on, instead of a list of names.
