# ir271: the places IR carries what the borrow checker reads (0.27.1)

Region slots, signatures and their universals, variance, the regions
dump; then Rust's operand rules (Copy, moves out of places, reborrows),
the guard's fake loans, captures as loans, the contracts' shared typing
(C3, C5, contract.move), and deferred initialization.

## What worked

- One function per rule, with its `// RULE:` id from borrowck.md: every
  walker of a type's slots (slots_in, field_map, bind_walk,
  slot_variances_in) is a few lines per type kind, and a new kind of
  slot (a by-reference capture's loan) was one helper used by all four.
- `--verify-places` grown with each IR change (slots against types, no
  copy of a whole `&mut`): every corpus case checked at every step, and
  it found the IR's own inconsistencies before the borrow checker did (a
  `for` loop's borrowed copy of a `&mut`, a shared reborrow typed by the
  coercion instead of the place).
- `volec probe` on the compiler itself: a guess about why a branch never
  ran (a closure literal's parts go through `agg_borrow` first) took one
  call to settle.
- `edit patch --pairs` for multi-hunk edits, checked once at the end.

## What cost time, ranked

1. Instances are clones of their template's node with `g = 0` and no
   lifetimes bound: whatever reads a function's generics or lifetimes
   must read the template's node (`fn_template`); impl lifetimes are
   keyed by `-node` (the Fn node), not by `-FNS index`.
2. Generated code under the user's edition: a derive's `match *self`
   and the contracts' companions are rust-edition functions by position,
   so Rust's operand rules moved a derived `clone`'s payload out of the
   reference. FN_DERIVED now keeps MVS's rules (but for f$pre); a pass
   that changes what an operand means should ask who wrote the code.
3. The runner's ERROR form: `// ERROR: :L:C: error[kind]` matches only
   with `-d short`; in the default form the position is its own line
   (`// ERROR: line L, column C`). corpus271 converted the corpus.
4. Two places to count an explain table (the array's length and its
   `*_COUNT` const), and self_explain is not in the cases a change to
   one error's code runs: the missing row for borrowck.static_mut_ref
   reached the release branch.
5. `unify` binds a type parameter to `decay_ref` of a reference (0.17's
   rule): `Vec::new_in` for a `Vec<&i64, Gpa>` annotation instantiated
   `Vec<*i64>` until it kept the reference in the rust edition.

## Gaps left, with their cases

- `&&'a str` (any `&` of a view) resolves to the view itself in the rust
  edition (front/check/resolve.vl: "`&T` of a view is the view"), so a
  reference to a view has no region slot of its own and `**s` of an
  `s: &&str` is a type error. Corpus case to add: `rust_b_ok_ref_to_view`.
- A `&mut [T]` view given to a call stays a copy (the places IR has no
  deref step on a view); D3.6 reads it as its reborrow, I7 allows it.
- Std's types count as Copy when glue-free with Copy arguments
  (`Range` copies, unlike Rust) until std2.
- A closure that moves a capture is FnOnce's (0.27.2): own.move_out.

## Tools

- [tool] `query grep` with `\(` or `|` in `--in` mode finds nothing
  where plain grep does, and the hook then blocks the grep.
- [tool] `edit insert` refuses when the program has an unrelated error
  and says only `try: ... --no-check`, not why.
- [tool] `edit patch NAME` with a name two modules define
  (`bind_pattern`) patches nothing and suggests the other one; the
  ambiguity is not said.
