# bc271: the borrow checker, NLL on the places IR (0.27.1)

## Verdict

Done as specified: docs/design/borrowck.md is the committed semantics
(D1.1 .. D17.7, M1 .. M7, I1 .. I7, R1 .. R12, L1 .. L8), and
compiler/src/places/borrowck/ implements it on ir271's tables: liveness,
constraints by variance, the solve, the loans in scope and the access
table, two-phase, fake loans, outlives, moves and initialization, dropck
with the container table, the per-instance dedupe, the verdict that
gates the optimizer's parameter alias facts. 18 codes, each with an
explain row; the corpus's negative cases pass except the ones named
ir271's or 0.27.2's; borrowck is 1.3% of typeck over the corpus.

## What to fix, with a tag

- [tool] `volec edit patch`'s `--new` text goes through the shell: a `'`
  inside it ends the quoted argument, and the error is a confusing
  "newline in string literal" from the check, not a quoting message.
  Three times a patch landed with `c"cannot write to '` cut at the quote.
  A `--new-file FILE` (the text from a file) or `edit apply` from stdin
  for one item would avoid it.
- [tool] `edit patch NAME --old .. --new ..` with several pairs aborts
  the whole call when one pair fails ("OLD 3 is not in ..."), and a
  pair's scope is the item named, so a struct field and a function body
  cannot be patched in one call without naming the file. Say in the
  error which pairs would have applied, or apply the independent ones.
- [tool] `query grep` has no alternation (`a\|b` gives 0 hits silently):
  say so, or support `-e A -e B`.
- [tool] The query-first hook blocks a test's own grep over compiler/src
  (tests/refactor/run.sh's self_explain pipeline) even when reproducing
  the test is the point; the override comment works but the first try
  costs a turn each time.
- [tool] `fix --only alloc` turned `Bck<Comp>` into `Bck<Gpa>` at every
  use when it made the struct generic: the allocator the uses need is
  the one the constructor names (`Vec::new_in(Comp {})`), not the
  default.
- [tool] `tests/run.sh` matches `ERROR:` directives in the human form by
  default, so a short-form directive (`:23:5: error[..]`) never matches;
  corpus271 rewrote 186 cases. The runner could say "the directive is in
  the short form; run with -d short or write `line L, column C`".
- [tool] `bootstrap/gate.sh --only threads` compiles compiler/src at -j1
  and -j8 from the working tree: an edit to compiler/src during the run
  makes the two differ and the row fail with no hint. A copy of the tree
  at the start, or a check that the sources are unchanged at the end.
- [tool] `place_body`'s fast path leaves the previous body's RPO and
  preds in the Body (elab.vl computes them only when it elaborates); a
  pass that runs after it must recompute them (check_body does) or read
  stale data. body_begin should clear them (ir271 M2 said it would).
- [lang] A struct holding `Vec<i64, Comp>` fields must be generic over
  the allocator (`alloc.field`), even inside the compiler where `Comp`
  is the one allocator: `Bck<A: Allocator>` with every use `Bck<Comp>`
  is noise for a type that never varies.
- [lang] `let _ = x;` of a `let` parameter is `own.move_out` ("cannot
  move 'pcx' out of a reference") under own_report_compiler: a `let _`
  of an unused parameter should be a read, not a move.
- [lang] No `|=`/`&=` on integers: every bitset update is `v[w] = v[w] |
  bit`.
