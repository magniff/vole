## Verdict

The edit loop on the compiler was fast and exact: every compiler change
went in through `volec edit insert|patch|replace`, the check hook removed
the imports a patch left unused, and `bootstrap.sh --dev --no-suite` took
10 s. Most cost came from facts the docs did not state in the place I
looked (a build leaves `#[test]` bodies unchecked; fields have no
privacy) and from the pre-commit hook asking for `// UNSAFE:` comments on
plain `NODES[n]` reads.

## What cost time, ranked

### 1. A `#[test]` body is not checked by a build, so the guide never checked them

To show "a test sees its module's private items" I compiled a program
whose test called another module's private function:
`volec --deny-warnings bad4.vl -o b4` printed `ok: built b4`, while
`volec check bad4.vl` printed `error[type error] 'clamp01' is private`.
tests/guide/run.sh compiles with a build, so the 15 `#[test]` items in
guide testing (and core, rust) were neither type-checked nor run. Fixed
in this branch (the runner runs `volec test main.vl` for a program with
`#[test]`). About 4 calls. A build that type-checks test items (without
emitting them) would have shown it at once.

### 2. Fields have no privacy, and nothing says so where a test author looks

The feedback asked "can a widget test keep the draw list private?". A test
in the root module reading `widget::Slider.active` (no `pub`) passed;
`guide modules#visibility` says "A struct's fields are as visible as the
struct (no private fields)". A field's `pub` is accepted silently, so
pathtrace's author made fields `pub` for nothing. 3 calls to establish. A
`pub` on a field could be a warning that says fields follow the struct.

### 3. The pre-commit hook refused my checker helpers for unjustified unsafe

`pre-commit: refused` with `compiler/src/front/check/body.vl:416: unsafe
without UNSAFE:/SAFETY: comments` (three sites). They read `NODES[n]` and
`TYPES[t]`, raw-pointer tables every checker function reads; their
neighbours (`branch_takes_type`, `synth_if`) are in the baseline
unjustified. I wrote the comments (1 turn). `front/check/literals.vl` has
private safe accessors (`node(n)`, `type_info(t)`) with the comments once;
a shared safe `node(n)`/`ty(t)` in front::ast would make new checker code
need no unsafe at all.

### 4. My first diagnostic note was reported twice

`literal_let`/`literal_help` dedupe on the position passed to
`literal_help` (`NOTED.push(pos)`, then `error_recorded_at(pos)`). I passed
the branch's position, not the error's, so the later use of the same local
gave a second error. One rebuild. The contract comment says "the error at
pos being made", which I read past; a parameter named `error_pos` would
have said it.

### 5. zsh ate `=NAME`

AGENTS.md says `tests/run.sh =NAME`; in zsh, `=word` is command-path
expansion: `tests/run.sh =std_num_fmt_f64` printed `(eval):1:
std_num_fmt_f64 not found` and ran nothing. Quoting (`'=NAME'`) works.
1 turn. AGENTS.md could show it quoted.

### 6. The query-first hook blocks whole lines

`... && sed -n '380,470p' compiler/std/num.vl; ... grep -rn "fmt_i64" compiler/std/*.vl tests/`
was blocked (6 commands, none ran) for the grep; and `sed -n
'741,760p;840,890p' compiler/std/num.vl` (two ranges of under 200 lines)
was blocked as a read of a 1,633-line file. The Read tool with an offset
did it. 2 turns. The hook could accept several small ranges.

### 7. Smaller

- `query items std::gpu::Blend` -> `error query.no-match: no module
  'std::gpu::Blend'` (a re-exported struct); `query show` of it worked and
  listed its methods.
- `std::mem::size_of::<T>()` -> `unknown type 'mem' | help: vole's std has
  no such module`: the message says "type" for a module path.
- `f64` has no `next_up` (Rust's since 1.86): `no method 'next_up' on type
  'f64'`; I used `f64_from_bits(f64_to_bits(x) + 1)`.
- `volec main.vl -l objc` for a std::gpu program: `ld: warning: ignoring
  duplicate libraries: '-lobjc'` (std::gpu links it; the guide runner
  still passes `-l objc`).
- A new guide anchor is only checkable after embed.sh and a rebuild
  (`volec guide window#checking-the-pixels-headless` reads the embedded
  text).

## Never used

`refactor`, `rewrite`, `probe`, `reduce`, `query impact|effects`, `batch`:
the changes were small and local. `volec explain`: the diagnostics I met
had their fix in the line.

## Fix list, in order

1. [lang] Type-check `#[test]` items in every build (emit nothing), so a
   broken test fails `volec main.vl -o x` as it fails `check`.
2. [diag] Warn on `pub` before a struct field (fields are as visible as
   the struct): "a field has its struct's visibility", with the edit.
3. [std] A safe `node(n)` / `ty(t)` accessor pair in front::ast for the
   checker (as literals.vl has privately), so new checker code needs no
   `unsafe` and no comments.
4. [docs] AGENTS.md: write `tests/run.sh '=NAME'` quoted (zsh).
5. [hook] query-first: accept `sed -n 'A,Bp;C,Dp'` when every range is
   under 200 lines; when one command of a line is blocked, say which
   others would have run alone.
6. [tool:query] `query items TYPE` for a re-exported type as for its
   definition.
7. [diag] "unknown type 'mem'" for `std::mem::...`: say "no module
   std::mem".
8. [std] `f64::next_up`, `next_down` (Rust's), for sweeps and tests.
9. [test] tests/guide/run.sh: drop `-l objc` for std::gpu programs
   (std links it) to silence ld's duplicate warning.
10. [docs] AGENTS.md: mention `tests/guide/run.sh -f compiler/guide/T.md`
    for one topic's examples.
