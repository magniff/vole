# ed270: the rust edition's front (0.27.0)

The four milestones: the switch and the parser, type checking, lowering
and running with regions built, and 56 hand-translated cases.

## What worked

- The edition as a mode of the one front, not a second parser: the
  0.19 "mixed" meanings already were Rust's references (`&T` a value,
  explicit `*`, receivers and fields through references), so turning
  `strict_at` off in a rust-edition file gave most of the surface for
  free. VOLE_SYNTAX=mixed was the probe that showed it.
- `edition.later` as one soft code with the feature and the release in
  the message: std2's 1,376 items could be checked at all, and the count
  per feature is a grep.
- Rewriting nodes in place for Deref, Index and the `for` items, as the
  checker's other desugarings do: no new node kinds, the IR builder and
  both code generators unchanged.
- A compiler without the 50-error cap, built to a scratch path, to count
  std2's errors by kind and feature (now `--max-errors=0`).
- Hand-translating existing cases in parallel (two helpers, a frozen
  compiler, a calibration set of five done first): 56 cases in an
  afternoon, and three front bugs found that no rust_ case had shown (a
  second `&TEMP` in a statement, temporaries dropped at the block's end,
  a fn of `&T` parameters as no `FnMut(T, T)`).
- `volec check --emit-places` as the test of the region tables: a
  PLACES line per loan in a tests/run case, no new runner.

## What cost time, ranked

1. The check-after-edit hook runs the last tested volec, which does not
   read the edition, and rewrites a rust-edition file it sees (`let mut`
   to `var`, `&mut T` to `inout T`, `&x` to `x`) after the command that
   wrote it. Scratch programs had to be written as .txt and compiled in
   the same command; a test file had to be checked with git diff.
2. Two merges of release-0.27.0 that moved SYMS and TYPES into the
   context and removed unneeded unsafe blocks (re-indenting whole
   functions): every ed270 line in those functions conflicted and was put
   back by hand on the release's text.
3. A miscompile of `let &x = r` and `for &x in &v` (the binding got the
   address): the let lowering's fast path for a name ignored PAT_DEREF.
   Found only by running the program; the checker and the verifier
   accepted it.
4. fmt was made to read the edition only after std2 had been formatted
   by it: `?Sized`, `<<T as Tr>::X>`, `fn union<'a>` and `impl<T> [T]`
   were rewritten in 19 std2 files and had to be put back by regex; a
   merge then brought the release's copy of the corrupted lines back.
5. The query-first hook blocks grep and sed over compiler/src even for a
   one-off look at a function the query tools cannot name (a string in a
   message, the lines around a conflict).

## Fix list

- [tool] check-after-edit.py: skip a file whose first line is `//
  EDITION: rust` while target/tools/volec does not read the edition
  (or use the worktree's target/volec for it).
- [tool] `volec check` with a flag for the error cap (`--max-errors N`),
  so a std2-sized check root can be counted without a scratch build.
- [tool] fmt: a roundtrip check that fails when formatting changes a
  file's tokens (not only its spaces), run before `fmt --all` writes:
  `:? Sized` was the same tokens, but `Option << ` was not.
- [tool] `edit patch` cannot add a struct field (it refuses the broken
  literals); `refactor field --add` does it, and the refusal could say so.
- [tool] `query grep` to honour a directory argument (it searches the
  whole program and ignores `compiler/src/tools/lsp`).
- [lang] The rust edition accepts some programs Rust rejects (0.19's
  leniencies): a `&T` of a plain value read where T goes, a place lent
  where `&T` goes, `let r = &n` used as n. Rust-valid programs mean the
  same; 0.27.1's checker should reject the rest.
- [lang] std2's 126 plain errors left, each with a release now:
  method_name_clash (61, `fmt` of Display and Debug on one type),
  SliceIndex signatures through `str` (str_slice_self), generic traits'
  default bodies, `unsafe fn` pointer types, `size_of` as a name, `use
  x::{self}`, `&&'a str` (the `&&` token in a type: a front bug).
- [lang] A named fn of `&T` parameters is no `FnMut(T, T)` for a plain T
  (`v.sort_by(by_n)` with `fn by_n(a: &i64, b: &i64)`): a closure is.
- [lang] `&v[0]` returned as `&'a &'b str` is refused with
  edition.std_by_value though no std function is involved; and `let a =
  ["x", "y"]` is `[[u8]]`, not `[&str; 2]`, in the rust edition.
- [lang] MVS bugs found on the way (fixed): a method's `where` on the
  impl's parameter bounded every method; conflicting impls on a slice
  named a random symbol.
