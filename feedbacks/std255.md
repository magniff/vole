# Feedback: std255, std's soundness bugs (Atomic<T>, statics under threads) and small std gaps

2026-10-29, release 0.25.5. compiler/std (sync/atomic.vl, fmt.vl,
alloc_check.vl, flat/arch.vl, flat/test.vl, flat/collections.vl, thread.vl,
math.vl, process.vl, sys.vl), compiler/src (front/traits.vl, generics,
check/interp.vl, front/tests, back/objfile/link_macho.vl), the guide (4
topics), 10 new test cases; five commits, about 1,000 lines without
stdsrc.vl.

## Verdict

Every item landed without a language change, but two needed the compiler:
no impl can cover every `*T` (`impl<T> Tr for *T` is refused), so the
`AtomicValue` bound for pointers is a checker intrinsic like `Ord`'s; and
sealing a trait has no construct, so a private type in the trait's
signature does it. The effect checker already keeps most std statics on
the main thread (`sync.global`); the real races were the ones it exempts
(std.fmt's statics, on trust) and the checking allocator.

## What worked

- `volec query context NAME` and `query show` for std items: the whole
  picture of `check_bounds`, `intrinsic`, `fn_instance` in three calls.
- `volec edit patch NAME --old A --new B --in OTHER --old C --new D`: three
  items in two files, one checked edit (SELF_BOUND_POS).
- `edit insert NAME --before` adding the imports the new text needs
  (`note edit.imports`).
- The `sync.global` error and `query effects --why`: they showed that
  stdin's statics and Linux's `sys_args` cannot be reached from a thread
  (`error[sync.global] 'thread::spawn' runs a closure on another thread,
  but it reaches a static var`), so the brief's list shrank to what is
  really reachable, and `guarded_static` (front/effects/infer.vl) named the
  exemption that made std.fmt's statics racy.
- `tests/run.sh -c /Users/magniff/workspace/tachyon/target/volec '=CASE'`:
  the same case on 0.25.4, to show it failing before (thread_std_statics:
  "got 'thread 3 line 1 abcdefghijklmnopqrstuvwxwhole 1 line ...'";
  thread_check_alloc; thread_local_no_use).
- `/usr/bin/time -l` "instructions retired" for the print benchmark under
  a load of 25 (wall time was noise).

## What cost time, ranked

### 1. The scratchpad is shared, and I deleted another agent's files

`mkdir -p $SCRATCH/t1` succeeded on a directory another agent had made a
minute before (a `git init` and a copy of compiler/). My `volec check` there
then read that copy's std (`unresolved import
'std::sync::atomic::AtomicValue'`), and I removed its compiler/ thinking it
was stray. Restored from `git archive HEAD`, but whatever the agent had
changed was lost. About 4 turns. Would have saved: a per-agent scratch
directory named in the brief, or a note in AGENTS.md: "the scratchpad is
shared by every agent of the session: make `$SCRATCH/<branch>/`".

### 2. The check hook's std is the tools binary's

From the first std edit to the end, every hook result said "1 error (1 as
before)": `compiler/std/sync/atomic.vl:100:22: error[type error] the trait
'AtomicValue' is not implemented for 'u32'`, because target/tools/volec has
no `atomic_bound`. Known (loop255), but it hid any new error behind "as
before" for the whole session; I ran `target/volec check` by hand after
each build.

### 3. `check` passes what the build refuses, inside std

`target/volec check tests/run/std_process_command_0255.vl` said `ok`; the
build said `error[type error]: no method 'starts_with' on type '[u8]' -->
<std>: line 50011` (the loader does not read the section of a slice
method another std section calls), and earlier `calling a method through a
raw pointer is unsafe` inside `Vec<*u8>::filled_in`. Each cost a rebuild
and a test run (3 rounds). Would have saved: check instantiating what the
build does, and the section index counting a std method call as a
dependency.

### 4. The in-house linker's list and its count

Adding four names to `LIBSYSTEM: [*u8; 406]` without `LIBSYSTEM_COUNT:
i64 = 402` made the last names unsearched, so every program fell back to
ld. Found only by tests/link's `FAIL internal` whose message is
"--linker=internal: ok: built prog;" (no reason); about 5 turns of `nm -u`
and `cmp -l` before reading the check. Would have saved: the count from the
array's length, or the test saying which condition failed ("the internal
linker gave ld's bytes").

### 5. Two things the affected plan found, one round each

- The book's effects transcripts: every printing program gained `sync`
  (`crate::main alloc(Gpa) io global sync panic diverge`). The effects
  pass hides print's lock by function names (front/effects/infer.vl:
  `is_print_lock`, "std.fmt.print_acquire" ...), and my fmt_guard was not
  on the list. Nothing in fmt.vl points at that list; a `#[effects(...)]`
  on the std function would say it where it is written.
- checkalloc_unsafe hung (`sample` showed check_new_block ->
  check_alloc_access -> __ulock_wait): with --check-unsafe the checking
  allocator's own raw accesses call back into it, so its new lock had to
  be reentrant. The runner said "timed out ... while the load average was
  above the 10 CPUs (now 24.57): a hang, or a machine loaded beyond
  that"; running the binary alone with `sample` settled it in one turn.

### 6. No way to name every pointer type, no sealed trait

`impl<T> Val for *T` is "a generic impl is for a generic struct or enum";
the brief assumed std impls for raw pointers. A checker intrinsic
(`atomic_bound`, matching the trait by name within std) was the smallest
way. Sealing uses `fn sealed_value(self) -> Sealed` with `Sealed` private;
a program's impl gets `error[type error] 'Sealed' is private`, with no
help line. Both are 0.26 language questions (`#[sealed] trait`, impls over
`*T`).

### 7. Grepping std

`target/volec query grep Atomic --code` searches compiler/src only;
`--in compiler/std` is `query.bad-in`. Every survey of std (its statics,
FMT_* uses, Atomic uses) went through `grep ... # no-query:`, and
alloc_check.vl and the sys tails are not in query's program at all, so
their edits were Python with `# no-tool:` (6 times).

### 8. `query effects FILE:LINE --why global` at a spawn

At the line of a `sync.global` error (its own try: line) it explained
main's `global` (`thread::spawn -> print_threads_started -> FMT_THREADED`),
not the closure's. I bisected by hand with seven one-line programs. Recorded
with tools/agent-feedback.

### 9. Smaller

- An impl method's self type was instantiated with std's position: the
  struct error read `<std>:23205:22: the trait 'AtomicValue' is not
  implemented for 'P'` (fixed here: SELF_BOUND_POS).
- `{x:#x}` is "invalid format spec"; f64's Display writes f64::MAX as 309
  digits, so the test compares instead.
- `volec test tests/refactor/testlang/main.vl` wrote
  tests/refactor/testlang/tests/snapshots/ and .volec/ into the tree.
- alloc_check.vl's unsafe blocks have no comments and are not audited
  (`return unsafe { align as *u8 };`).
- The guide's examples need `compiler/guide/embed.sh` after an edit; I
  remembered it from run254's feedback, not from a message.

## Never used

`probe`, `reduce`, `rewrite`, `refactor`, `batch`, `fix --suggested`, `undo`:
no error needed them; the edits were new code or files outside edit's
reach.
