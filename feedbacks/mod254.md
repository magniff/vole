# Feedback: mod254, the plan for modernizing compiler/src and its first step

2026-10-29, release 0.25.4. The inventory and the plan
(docs/design/modernize-0254.md), a Vec<i64>/IntVec benchmark, a new tool
(`volec fix --only unneeded-unsafe`, tools/fix/unneeded.vl, 330 lines)
run over compiler/src (938 unsafe blocks gone, 225 files, +12.7k -14.1k
lines, mostly re-indentation), the two embed.sh generators, and a pilot
(tools/fixunsafe.vl's IntVecs as `Vec<i64, Comp>`).

## Verdict

The compiler's tools are good enough to plan a 95k-line migration from
the command line: `query unsafe --json`, `query refs --count`, `query
items --kind static` and `rewrite --list` gave every number in the plan
without reading files, and the checked edit engine made a 225-file edit
safe to apply in one second. What is missing is at the edges of each
tool: no tool removes an unneeded block (I wrote it), `rewrite` cannot
splice a block's statements, a type change cannot be one checked edit,
and the edit tools write generated files as if they were sources.

## What worked

- `volec query unsafe --json --no-std` (0.9 s): one object a site with
  its operations (`static-index x5, index x2`), enough to attribute the
  4,419 blocks to idioms and to the tables they index, offline, in a
  script. `--summary` gave the before/after lines for the report.
- `volec query refs NAME --count` and `query refs NAME --all` with the
  kind column (`init`, `type`, `use`): 2,823 IntVec references split into
  1,387 literals, 1,206 types, 230 imports in one call.
- `volec query items --kind static --all`: every static with its type, so
  the 242 raw table pointers and 519 IntVec statics were a `grep` away.
- `volec query text FILE:A-B` when the hook refused `sed -n` in a loop.
- The fix infrastructure: a new mode is a function returning edits
  (`edit_replace(start, end, buf)`); the engine checks the edited program
  and writes atomically. `fixed 933 unneeded unsafe blocks, 5 left as
  they are (query unsafe lists them)	223 files	+13042 -14502 lines` in
  1.4 s, and `volec check` clean after it.
- `volec rewrite '$v.data[$i]' '$v[$i]' --where '$v: IntVec' --in
  crate::tools::fixunsafe` (typed, 39 sites) and `--list` to see the
  sites first; `note rewrite.types` named the `*IntVec` sites it skipped
  with the exact `--where` to use.
- `volec same-output OLD -j 4`: 32,760 compilations in under 6 minutes,
  and it kept the differing ones in target/same-output for checking.
- `bootstrap/bootstrap.sh --dev --no-suite`: 13 s for a build with its
  fixpoint, each time.
- The messages: `unknown attribute 'noinline' (expected repr, ...,
  inline(never), ...)` fixed itself; `cannot infer type parameter 'T' of
  'Vec::new_in' | help: ... give the variable a type` said exactly what to
  write; the check hook's `suggested, not applied: + use
  crate::base::comp::Comp;` was right.

## What cost time, ranked

### No tool removes an unneeded unsafe block (about 1.5 hours, the tool itself)
`query unsafe` labels 938 blocks `none (unneeded)`, `explain
unsafe.unjustified` says "remove it", and nothing does. `volec rewrite
'unsafe { $b }' '$b' --in compiler/src/main.vl:192 --dry-run` printed
`note rewrite.none: nothing matches 'unsafe { $b }'` for a 7-statement
block (`$b` matches one statement; `$s...` alone is `rewrite.pattern`).
I wrote `fix --only unneeded-unsafe`. Saved by: a rewrite replacement
that is a block's statements (`'unsafe { $s... }' '$s...'` spliced into
the block around, with a scope check), or the fix mode existing.

### Generated files are edited like sources (about 20 minutes)
The fix rewrote front/stdsrc.vl and arch/tables.vl (`// Generated by
compiler/std/embed.sh ... (do not edit)`); nothing said so. I found it
from `git diff --stat` (tables.vl +2902 -2902). The generators had to
change instead (`echo "    unsafe {"` lines and the indentation of
`lines()`), and I first dropped one `echo "    }"` too many: `check`
then said `unresolved import 'crate::front::stdsrc::std_sys_source'`,
far from the cause. My tool now skips `// Generated by` files
(tools::fmt::generated already existed for fmt). Saved by: the edit
engine refusing (or warning on) a file whose first line says it is
generated, naming the script.

### A type change cannot be one checked edit (about 30 minutes, the pilot)
Turning a module's IntVecs into `Vec<i64, Comp>` takes four rewrites, and
each breaks what the next one reads, so each needs `--no-check`
(`warning edit.breaks: 11 new errors; written anyway`). `refactor
--script`, the tool for "checked once", failed at its fourth line:
`error rewrite.usage: unknown option '--root' (...)` for `rewrite --text
IntVec 'Vec<i64, Comp>' --word --code --files ...`: the script passes
`--root` and `rewrite --text` refuses it, and the three typed rewrites
before it were thrown away. Then `rewrite --text ... --diff` wrote (I had
meant to look: `--diff` is "show what was written", not a dry run) and
it rewrote the `use crate::base::{..., IntVec, ...}` line into `use
crate::base::{FILES, Vec<i64, Comp>, SRC, ...}`; `volec undo` took it
back. Four `$v.count` sites nested in the first rewrite's sites were left
(`note rewrite.untyped: 4 sites are left`) and needed a second run with
the new type. Saved by: `refactor --script` accepting `rewrite --text`;
a `refactor type OLD NEW --in MODULE` that changes a type's spelling in
types only (not in `use` lines).

### A Vec local needs its type written (5 minutes)
`var ranges = Vec::new_in(Comp {});` then `ranges.push(s)`: `cannot infer
type parameter 'T' of 'Vec::new_in'`. Five locals. The message is clear;
the rewrite that made them could have written `Vec::<i64, Comp>::new_in`
from the pattern's typed hole, or the checker could infer T from the
first push.

### `use a::f;` and a local `fn f` together are accepted (10 minutes)
`edit patch` added `use crate::tools::fmt::generated;` for a name my
patch used before I had defined it (`note edit.imports: added the imports
the new text needs`); I then inserted my own `fn generated`, and `check`
was clean with both. A small program shows it: `mod a; use a::f; fn f()
-> i64 { 2 }` builds and prints 2, no error, no `use.unused`. Saved by: an
error for an import and an item of the same name in one module.

### The hook and reading compiler source at scale (about 10 minutes)
The query-first hook blocked `for fl in ...; do sed -n "${a},${b}p"
compiler/src/$f; done` (the range is a variable) and `cat
compiler/src/tools/fixunsafe.vl` (346 lines); `query text FILE:A-B` and
the Read tool did the job. To attribute 4,419 unsafe blocks to the tables
they index, I needed each block's text: no query returns it, so a Python
script read the files with `# no-query:` (recorded). Saved by: `query
unsafe --json` giving each block's end line, or its operations' operand
names (`static-index(NODES) x5`), which would make the attribution a
query.

### `query grep --count` and generated text (5 minutes)
`volec query grep 'c"' --code --count` printed `0` (c-literals are
strings); `--strings --count` printed `16336`, including 1,009 in the
generated std text, and `--count` prints only a total: the per-file table
comes only without `--count`. Saved by: `--count` per file, and a way to
leave generated files out.

### Static Vecs need a constant allocator (10 minutes)
`static var NODES: Vec<Node> = Vec::new();` is `allocation is explicit:
pass an allocator`; `guide --find static Vec` says "A static cannot hold
a Gpa". base/comp.vl's zero-sized `Comp` (unused since 0.18: 5 refs, all
its own) is the answer and `Vec::new_in(Comp {})` in a static works, but
nothing in the guide or the error points to the pattern of a zero-sized
allocator for statics.

### Texts pinned in five places, found by a 10-minute run (about 25 minutes)
Adding one word to fix's `--only` list and one sentence to `explain
unsafe.unjustified` broke four transcripts (fixes.t, alloc016.t,
std015.t, unsafe0253.t) and the guide runner's rule that every `--help`
has at most 15 lines (`FAIL help-fix: volec fix   every machine-applicable
fix: ...`, which says neither "15" nor "too long"). Two I found by
running the transcripts that name `fix`; the other three only from
`tests/affected.sh`, whose plan was `2584 of 2765 cases` (a change to
every file is "broad"), 10 minutes at load 12 to 30. Saved by: a
`tests/run.sh texts` filter of the cases that pin a tool's own wording,
and the help check's failure saying `16 lines, at most 15`.

### Timing under load (noted, not lost)
The benchmarks ran at load average 3.1 to 4.1 (`uptime`); the first
version of the sum kernel was 0.06 ns an element because the effects
system proved `sum_index(v)` pure and the 5 calls became one; a salt
argument fixed it. The assembly (`volec -O2 --emit-asm`) was the
evidence, not the times.

## Never used

- `volec probe`, `reduce`, `test`: nothing failed at run time.
- `refactor signature|field|variant|move`: the plan's steps need them
  (step 7), the first step did not.
- `volec batch`: each step needed its own output before the next.
- `query context`: `query show` of a few named items was enough for the
  tool's code paths; the context's callers list would have been large
  (fix's command).

## Fix list, in order

1. [tool:fix] Keep `fix --only unneeded-unsafe` (this branch) and run it
   after every modernization step; teach `query unsafe --summary` to
   print its `try:` when unneeded > 0.
2. [tool:edit] Refuse, or warn on, an edit of a `// Generated by ...`
   file, naming its script (the fix mode now skips them; `rewrite`,
   `edit patch --all` and `fix` in general do not).
3. [tool:refactor] `refactor --script` must accept `rewrite --text`
   lines (it passes `--root`, which `rewrite --text` refuses), so a type
   change is one checked script.
4. [tool:refactor] `refactor table X --count X_COUNT --cap X_CAP`
   (planned in 0.18, never built): the triple to `Vec<T, Comp>`, step 3 of
   the plan.
5. [tool:rewrite] A replacement that is a block's statements spliced into
   the enclosing block (`'unsafe { $s... }' '$s...'`), with the scope
   check fix --only unneeded-unsafe does.
6. [tool:rewrite] `rewrite --text` never rewrites inside `use` lines when
   `--code` is given and the new text is not a path (it made `use
   crate::base::{FILES, Vec<i64, Comp>, SRC}`).
7. [lang] An import and an item of the same name in one module: an
   error (today the local item wins silently).
8. [lang] Infer `Vec::new_in`'s T from the first use (`push`), or have
   rewrites write the turbofish their typed holes know.
9. [tool:query] `query unsafe --json`: each operation's operand
   (`static-index(NODES)`), and the block's end line.
10. [tool:query] `query grep --count`: per file, and a flag to leave
    generated files out.
11. [docs] guide allocators: a zero-sized allocator (`base::comp::Comp`)
    is how a static holds a `Vec`; say so where "A static cannot hold a
    Gpa" is said.
12. [test] The guide runner's `help-CMD` failure says why (`16 lines,
    at most 15`); a filter for the transcripts that pin a tool's wording.
13. [lang] The optimizer's Vec facts (plan §2): hoist a `let` Vec
    parameter's header out of loops; a sealed container's buffer does not
    alias its header (bounds checks of `v[i] = ...` loops on an `inout`
    Vec).
