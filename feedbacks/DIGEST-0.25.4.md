# Feedback digest after 0.25.4

**Sources.** Eight agents' files from 0.25.4's branches (feedbacks/{bugs254, fb254, headless254, mod254, opt254, run254, stdunsafe254, table254}.md) and the user's three project retrospectives (galaga.md, nes.md, pathtrace-ui.md). Each item below is grouped by theme and ranked by how many files raise it and what it cost. A tag gives its area.

**Already done and left out.** These items from galaga.md and nes.md have since shipped: tools' program roots and `--root` (0.25.2), `use.unused` (0.25.2), `edit patch --all`, `agent-feedback --list/--find`, the guide's GPU skeleton (0.25.3), and golden-image checks (0.25.4's scripted event loop, `shot`).

## The picture

The compiler's loop got the most praise in every file: `check` in well under a second, exact `try:` lines, `edit patch` checked edits, the check hook's mechanical fixes, and `volec test` comparing -O0 with -O2.

Almost none of the cost was in the compiler. It was in three places:
- **the hooks**, which block or misread legitimate work;
- **the edit tools**, which can't express several dependent edits as one checked call;
- **the test harness**, where transcripts pin std's shape and the shell eats `=NAME`.

The language questions are fewer but weightier: private fields, what `#[sealed]` means, `Atomic<T>`, and statics under threads.

Never used, by nearly every agent: `probe`, `reduce`, `batch`, `query impact`/`effects`, `undo`. `refactor` and `rewrite` were reached for only where a task was a mechanical rewrite. The `rewrite` tool has these gaps: it can't splice a block's statements into the block around it, it rewrites inside `use` lines, and `refactor --script` refuses `rewrite --text` lines.

## 1. Hooks (6 files, plus the orchestrator three times today)

1. **[hook] The check hook reads the std embedded in its binary, not the tree.** A new std item gives a false `unresolved import` until a build whose suite passed is installed. Raised by stdunsafe254 #2, headless254 #5 and #7, and the orchestrator: three false stop-hook failures today (`std::sys_c_strerror_r`), plus 0.25.3's 16 false failures. bugs254 made the hooks notice an older *version*, but the same version string with a different std still slips through. Fix: the hook checks with the tree's std, or compares the embedded std's hash with the tree's. **Highest value of all.**
2. **[hook] query-first blocks work it shouldn't:**
   - reads and rewrites of a `.vl` file the session itself created (run254 #1, opt254 #5);
   - `sed -n 'A,Bp;C,Dp'` when every range is small (fb254 #5);
   - grep or sed of non-`.vl` files under compiler/std (stdunsafe254 #8);
   - a script that only *reads* compiler source (opt254 #5).

   Also, one blocked command blocks the whole line, so it should say which other commands would have run alone (fb254 #5).
3. **[hook] After an edit of compiler/guide/*.md, say that `compiler/guide/embed.sh` is needed** (run254 #3).

## 4. Language decisions (for the user)

1. **[lang] Private fields.** Fields are as visible as their struct, and `pub` on a field is accepted silently (fb254 #2). In std that makes these forgeable in safe code (stdunsafe254 #9): `Window.ns`, std::objc's `Ref`/`Id` (`pub ptr`), `RawSurface::MetalLayer`, `HashMapIter`. `Atomic`, `RawLock` and `Once` can't even be sealed, because statics build them from literals. The options:
   - (a) private fields with Rust's module-privacy rule;
   - (b) `#[sealed]` by default for types with raw-pointer fields, plus a const-constructor path for statics;
   - (c) keep the rule, warn on a field's `pub`, and make the std types unforgeable by other means.

   Two agents hit this independently today.
2. **[lang] What `#[sealed]` promises.** opt254 had to narrow an optimizer fact to a list of names, because sealing Mutex silently widened what the fact relied on (opt254 #9). A checked property, "no `let` method writes a field, through a raw pointer either", would let the optimizer rely on it safely.
3. **[lang] `Atomic<T>` bound to integer, bool and pointer types** (stdunsafe254 #10). Today `Atomic` of a struct crashes at -O2, and `Atomic<f64>::fetch_add` adds the bits as an integer. It's a soundness bug, so it should be fixed regardless.
4. **[lang] Statics are safe to mutate while threads exist**, so safe code can race (FMT_OUT, `sys_args`, the STDIN statics) (stdunsafe254 #11). This needs a rule, for example a static mutable only from unsafe code or through `Sync` types.
5. **[lang] Smaller items:**
   - check `#[test]` bodies in every build (fb254 #1);
   - an import and a local item of the same name is an error, not a silent shadow (mod254 #7);
   - infer `Vec::new_in`'s T from its first use (mod254 #8);
   - float and text holes in contract messages, and floats in `assert` (bugs254 #9, #10);
   - f32 to f64 widening: allow it or explain the refusal (bugs254 #3);
   - a `\` line continuation that keeps indentation (run254 #7);
   - unsafe-check generic bodies before instantiation (stdunsafe254 #4).

## 5. The compiler's output and speed

1. **[build] A zero-initialized static is written as data, not bss**, and statics no program reaches are still emitted. One `[u8; 65536]` cost every program 64 KiB of object and 46% of a hello world's build time (stdunsafe254 #16).
2. **[build] A compiler linked by `volec -o` ran its self-compile in 357G instructions, against 54G for the same source with `-c` and linked by `cc`** (opt254 #8). Not checked yet: likely a different default optimisation level between the two paths rather than the linker. Verify first; if it is the default `-O`, document it in `--help`.
3. **[build] Drop a bounds check that an explicit `< len` test dominates** (stdunsafe254 #15). This is why `[T]::get` keeps an unsafe read for 1.9x.
4. **[tool] Performance tooling:** `--time-passes=instructions` per phase without a special build, and `--vec-stats=FN`, which says why a loop was not vectorized (opt254 #1, #2).
